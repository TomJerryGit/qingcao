# 完整 UI 隔离差距评估（Sprint 3 / task-26）

日期：2026-11-18
范围：插件子进程 UI（AI 助手、调试器）与宿主主窗口的隔离边界。

## 1. 现状

已实现：

- 子进程控件树协议 `core/remote_ui.py`（label/button/line_edit/check_box/text_view/box）；
- 宿主渲染器 `ui/remote_ui_renderer.py` + 面板/对话框承载；
- 事件回传队列 + 子进程 `RemoteUIClient` 推送/轮询；
- 动作白名单派发（`ai_apply_result:*`/面板打开等）；
- AI 隔离面板、AI 结果对话框、调试面板已迁移；
- 子进程**不持有主窗口/宿主 QWidget**。

未实现（“完整”二字的差距）：

1. 子进程不能自绘任意 Qt UI（仅协议控件）；
2. 不支持控件树之外的复杂控件（表格/分页/富文本编辑/菜单栏）；
3. 无跨进程窗口句柄嵌入（HWND foreign window）；
4. 事件语义有限（仅 click/text/checked + 白名单动作）。

## 2. 三种路线对比

| 路线 | 做法 | 成本 | 风险 | 结论 |
|---|---|---|---|---|
| A. 远程控件协议（现状） | 子进程控件树 → 宿主原生渲染 | 低（已落地） | 控件种类有限；动作需白名单 | ✅ 生产推荐 |
| B. HWND 跨进程嵌入 | 子进程创建窗口，宿主 `SetParent` 嵌入 | 高（4–8 周） | 焦点/DPI/无障碍/输入法/崩溃传播/权限提升 | ❌ 暂不采用 |
| C. 子进程独立顶层窗口 | 子进程自建窗口，宿主不嵌入 | 中（1–2 周） | 窗口割裂、任务栏/模态/焦点混乱 | ⚠️ 仅特殊插件 |

## 3. 推荐决策

**保持 A（远程控件协议）作为唯一生产 UI 隔离方案**：

- 安全边界清晰：子进程永不获得宿主窗口句柄；
- 已有动作白名单 + 事件校验 + 控件数量/文本上限；
- 可通过扩展协议覆盖大多数插件 UI；
- 避免 HWND 嵌入带来的权限与稳定性风险。

## 4. 后续扩展路线（按需）

1. 控件类型：`table`、`combo`、`tabs`、`menu`、`rich_text`；
2. 事件：`selection_changed`、`double_click`、`submit`；
3. 动作：注册式命令（插件声明 command → 宿主白名单校验执行）；
4. 体验：焦点顺序、键盘导航、主题色同步、a11y 属性继承；
5. 测试：控件树快照、事件回放、动作权限负例。

## 5. 触发重新评估的条件

- 第三方插件明确需要宿主无法提供的复杂控件；
- 远程协议扩展成本超过 2 周；
- 出现必须嵌入原生窗口的安全/合规需求（需独立安全评审）。

## 6. 成本估算

| 项 | 估算 |
|---|---|
| 远程控件扩展（表格/下拉/分页 + 命令注册） | 1–2 周 |
| HWND 嵌入原型 + 安全评审 | 4–8 周 |
| 子进程独立窗口包装 | 1–2 周（不推荐） |

## 7. 结论

“完整 UI 隔离”在安全语义上已达成（子进程不持有宿主 UI）；在“子进程自绘任意 UI”语义上未达成。当前决策：**不追求 HWND 嵌入**，以远程控件协议渐进扩展。

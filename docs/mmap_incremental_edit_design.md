# mmap 增量编辑设计（v2.18.x P3 预研）

## 目标

大文件（>10MB）单行/局部编辑不再全量重写，降低写盘与内存峰值。

## 基准（`tools/bench_mmap_edit.py`）

对 20MB 文本修改中间一行，对比：

| 方式 | 复杂度 | 说明 |
|---|---|---|
| 全量重写 | O(n) 读 + O(n) 写 | 当前保存路径 |
| mmap 原地补丁 | O(行偏移) + O(改动长度) | 要求**字节长度不变** |

结论（运行输出）：mmap 补丁显著快于全量重写（详见 JSON）。

## 接入条件（后续实现）

1. 仅当**新行与旧行 UTF-8 字节长度一致**时走 mmap；
2. 不一致时回退全量重写（或分段移位，复杂度上升）；
3. 编辑期间需保证文件未被外部修改（mtime/size 校验）；
4. Windows 下写映射需要 `r+b` 且不允许其他句柄独占；
5. 撤销/重做仍由内存层负责，mmap 仅用于**保存**。

## 风险

- 字节长度变化（中文/emoji）频繁，命中率有限；
- 断电/崩溃时原地写可能导致文件半损坏 → 需写前备份或 journal；
- 与现有 provider 释放句柄策略存在交互，需单独设计。

## 建议

作为 v2.19+ 独立立项，先实现"等长行替换"试点并加 journal 备份。

# 8 个孤立模块 · 产品决策简报

> 结论先行：**8 个都是可运行的完整代码，不是空壳**。
> 但它们要变成"产品功能"，需要的不只是接线 —— 每个都缺一块**产品决策**。
> 本简报基于实际实例化 + 核心 API 实跑（非静态阅读）。

实际发现的**小缺陷**（接线的顺手修）：

* `code_templates.format_template(name, **kwargs)` 的形参名 `name` 与模板占位符
  `{name}` **冲突** —— `format_template("py_class", name="MyClass")` 会抛
  `TypeError: got multiple values for argument 'name'`。改形参名即可。

## 逐模块决策卡

### 1. `ui/snapshot_manager_dialog.py`（154 行）+
`core/snapshot.py`（191 行）
**是什么**：把"当前所有打开的文件 + 光标位置 + 窗口布局"存成一个快照，
随时一键恢复。对话框已有 新建快照 / 恢复 / 删除 / 关闭 四个按钮。

| 维度 | 评估 |
|---|---|
| 完成度 | **高** —— 后端 + 对话框都完整，`SessionManager` 已在采集同类状态 |
| 缺什么 | 只缺一个菜单项 + 把 `TabManager` 状态喂给 `SnapshotManager` |
| 接线成本 | **低** |
| 用户价值 | **高** —— "老板突然叫我切任务，回来接着干" 是真实痛点 |
| 风险 | 低（本地文件操作） |

**建议：做（第一优先）**

### 2. `core/code_templates.py`（240 行）
**是什么**：8 个现成模板（Python 类/函数/测试/主程序、JS 函数/类、
`.gitignore`、`README`），带占位符替换。

| 维度 | 评估 |
|---|---|
| 完成度 | **高** —— 模板代码是真实字符串，格式化可用 |
| 缺什么 | 「新建文件」时的模板选择 UI（现有 `新建` 是空白标签） |
| 接线成本 | **最低** —— 一个下拉对话框 + 写进新标签 |
| 用户价值 | 中 —— 对"每次新建都要手敲 class 骨架"的人有用 |
| 风险 | 低 |

**建议：做（第二优先，成本最低）**

### 3. `ui/task_panel.py`（189 行）+
`core/project_tasks.py`（131 行）
**是什么**：项目任务树 —— 定义任务（如"构建"/"测试"）并一键运行、看输出。

| 维度 | 评估 |
|---|---|
| 完成度 | **高** —— 面板 + 后端都完整（`TaskPanel` 有树、运行/停止按钮） |
| 缺什么 | **"项目"这个概念本身** —— 任务属于哪个项目？配置存哪？ |
| 接线成本 | 中 —— 面板可加为 dock，但需要项目根语义 |
| 用户价值 | 中高（对项目型用户） |
| 风险 | 低 |

**建议：与 `workspace` 一起做**（见下）

### 4. `core/workspace.py`（116 行）
**是什么**：多根工作区模型 —— 一个窗口挂多个根目录（VS Code 风格），
每个文件能反查属于哪个根。

| 维度 | 评估 |
|---|---|
| 完成度 | **高（纯模型）** —— 但有**零 UI** |
| 缺什么 | 工作区面板/根目录列表/搜索范围限定 —— 是一块新 UI |
| 接线成本 | **中高** —— 需要新面板 + 目录树集成 + 全局搜索按根过滤 |
| 用户价值 | **高** —— Notepad++ 的对标项里"多根工作区"是明确缺口 |
| 风险 | 中（要改目录树与搜索的作用域） |

**建议：做，但作为独立批次**

### 5. `core/project_config.py`（133 行）
**是什么**：项目级配置（`.qingcao/` 目录 + JSON），项目内共享
tab 宽度/换行/编码等设置，覆盖用户全局偏好。

| 维度 | 评估 |
|---|---|
| 完成度 | **高（纯模型）** —— 但有**零 UI** |
| 缺什么 | ①「项目根」如何确定（当前文件向上找？用户指定？）②设置 UI |
| 接线成本 | 中 |
| 用户价值 | 中 —— 团队协作时统一风格有价值，个人用户感知弱 |
| 风险 | 低 |

**建议：与 `workspace` 配套做**（项目根语义一次定义两处复用）

### 6. `core/key_sequence_manager.py`（190 行）
**是什么**：VSCode 风格多键序列（`Ctrl+K Ctrl+S`）—— 前缀键等待 + 超时取消。

| 维度 | 评估 |
|---|---|
| 完成度 | **高** —— 注册/等待/触发/超时都实测正常 |
| 缺什么 | 接进 QScintilla 的按键事件链；与现有快捷键体系共存 |
| 接线成本 | 中 |
| 用户价值 | 中 —— 只有习惯多键序列的用户需要 |
| **风险** | **中高** —— 前缀键会"吃掉"按键；现有 `tests/test_shortcuts.py` 守护着
  一堆冲突敏感项，接入需非常小心 |

**建议：做，但必须配冲突检测测试**

### 7. `ui/snippet_market_dialog.py`（222 行）+
`core/snippet_market.py`（133 行）
**是什么**：代码片段市场 —— 按语言/关键词搜索、一键安装片段。

| 维度 | 评估 |
|---|---|
| 完成度 | 对话框完整（刷新/安装/语言筛选/搜索），但后端是
  **`SnippetMarketClient` —— 一个网络客户端** |
| 缺什么 | **市场服务器本身** —— 没有服务端，这个功能没有内容可下载 |
| 接线成本 | 低（接 UI）；但**产品成立成本高**（要运营一个片段市场） |
| 用户价值 | 取决于是否有内容 |
| 风险 | 中（网络 + 信任第三方片段代码） |

**建议：暂缓 —— 需先决定"是否有官方片段服务"**

### 8. `ui/collab_dialog.py`（231 行）+
`core/collab.py`（235 行）
**是什么**：实时协作 —— 启动主机 / 加入会话 / 房间名 + 端口，P2P 协作文本。

| 维度 | 评估 |
|---|---|
| 完成度 | 对话框与协议层都完整（含 Insert/Delete/Replace 命令） |
| 缺什么 | 实际网络可达性、NAT 穿透、权限、冲突解决、安全模型 |
| 接线成本 | 中 |
| 用户价值 | 小众（编辑器级实时协作多由专业产品承担） |
| **风险** | **高** —— 网络功能 + 安全面 + 难以在无网络环境验证 |

**建议：暂缓（或明确只做局域网演示）**

## 推荐决策

**批次 A（低风险、可立即交付，约 1 天）**
1. `snapshot` —— 补菜单项 + 接 TabManager 状态
2. `code_templates` —— 新建文件时可选模板（顺手修 `format_template` 参数冲突）

**批次 B（需要设计一次"项目"概念，约 1~2 天）**
3. `workspace` + `project_config` + `task_panel` 一起做 ——
   三者共享同一个「项目根」语义，分开做会各造一套。

**批次 C（谨慎，需专项测试）**
4. `key_sequence_manager` —— 必须配快捷键冲突检测

**暂缓（需产品成立条件）**
5. `snippet_market` —— 等"是否有官方片段服务"的决定
6. `collab` —— 网络 + 安全，建议单独立项

## 债务棘轮影响

做完批次 A → 8 → 6；批次 B → 6 → 3；批次 C → 3 → 2；
剩下 2 个（market / collab）需产品决策，可保留在台账里并注明原因。

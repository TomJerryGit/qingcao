# 首个 Lite 版发布计划（v3.0 Lite）

## 目标

用最小功能集交付一个“能装、能跑、能上手、能维护”的免费版本。

## 范围

保留：编辑、搜索、Python 运行/调试、内嵌控制台、AI 可选、2–3 套主题、安装器。
隐藏/冻结：插件市场、评分、使用统计、主题市场、Java 深度支持。
明确标注：Java 仅实验性单文件运行；非 Windows 平台不支持。

## 时间表（约 8 周）

| 周 | 事项 | 产出 |
|---|---|---|
| 1–2 | 功能冻结、隐藏入口、发布 workflow 单流程化 | PRODUCT/冻结清单/单 workflow |
| 3–4 | 主题与菜单视觉回归、首次启动向导、README 重写 | 视觉基线、5 分钟上手文档 |
| 5–6 | 5–10 名真实用户任务测试 | 阻断点清单、修复 |
| 7 | 全量回归、安装器验证、崩溃日志演练 | 发布候选 |
| 8 | 发布 v3.0 Lite | Release + 安装器 + 文档 |

## 发布检查清单

- [ ] `python -m tools.check_version` 通过
- [ ] `ruff check .` 通过
- [ ] 全量测试通过（或仅已知 flaky 放行）
- [ ] 冷启动 ≤ 2 秒
- [ ] 安装/卸载/覆盖安装通过
- [ ] 4 套主题截图无不可读文字
- [ ] Release 单 workflow 自动完成并含 4 资产
- [ ] README 只描述保留功能

## 维护节奏

- 每月 1 次稳定版；
- 紧急安全/阻断修复例外；
- 每周固定 6–8 小时：issue 分类、回归、文档；
- 功能请求进入 backlog，不承诺排期。

## 成功指标

| 指标 | 目标 |
|---|---|
| 真实用户 | ≥ 10 |
| 核心任务完成率 | ≥ 80% |
| 发布成功率 | ≥ 95% |
| 月维护时间 | ≤ 32 小时 |
| 崩溃可定位 | 有日志可导出 |

## 风险与应对

| 风险 | 应对 |
|---|---|
| 单人 burnout | 冻结非核心、月度发版 |
| 发布链路失败 | 单 workflow 自包含，失败自动阻断 |
| 用户要求 IDE 功能 | 明确非目标，引导用 PyCharm/VS Code |
| AI Key/成本 | 用户自备，本地 Ollama 优先 |
| 安全责任 | 默认无遥测、插件权限提示、签名校验 |
